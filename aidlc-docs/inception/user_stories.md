> AWS Summit Japan 2026 AI-DLC ハッカソン提出用 / Inceptionフェーズ成果物

## 1. プロダクト概要

### 1.1 プロダクト名（仮）
**HomePilot** — 家庭を自動操縦するスマホアプリ

### 1.2 コンセプト
共働き世帯の「家庭の司令塔」をAIが代行するスマホアプリ。

ペルソナである中村美咲のような共働き家庭の意思決定者は、家事そのものではなく「家庭全体の意思決定負荷」に疲弊している。本プロダクトは、家庭運営の判断・調整・実行を **HomePilot が美咲の代わりに自動操縦** することで、ユーザーを徹底的に「考えなくていい人」にダメにする。

ハッカソンテーマ「人をダメにするサービス」に対しては以下の方針で応える:
- **判断を奪う**: 美咲が下していた数十の小さな判断をシステム側で自動化／提案化する。
- **調整を奪う**: 夫・保育園との調整コミュニケーションを代行する。
- **記憶を奪う**: 期限・在庫・予定の保持責任をシステムに移管する。
- **オプトインで完全自動**: 利用者が望めば「事後報告のみ」モードまで踏み込み、人をさらにダメにする。

### 1.3 ペルソナ要約
中村美咲（36歳・首都圏在住・IT企業PM・時短勤務・夫＋6歳/2歳の子の4人家族）。
家事・育児・仕事の並列処理で疲弊。求める価値は「効率化」ではなく「**判断負荷の削減**」「**考えること自体からの解放**」。

### 1.4 MVPスコープ（優先順）
1. **第1優先**: 保育園関連（持ち物・連絡帳・行事）
2. **第2優先**: 家事分担（夫との調整）

その他領域（献立／買い物／通院／送迎調整等）は本MVPのスコープ外（将来拡張）。

### 1.5 提供形態・技術前提
- スマートフォン向けアプリ（iOS/Android）
- AWS上で稼働（具体構成は実装フェーズで決定）

## 2. アクター定義

| ID | アクター | 役割 | 主な接点 |
|---|---|---|---|
| A1 | **美咲（主ユーザー）** | 家庭の司令塔。意思決定の起点。本サービスにダメにされる対象。 | スマホアプリ |
| A2 | **夫** | タスクの受け手・実行者。美咲との調整対象。 | スマホアプリ |
| A3 | **保育園** | 情報源（お便り・連絡帳・行事）／連絡対象（欠席連絡・連絡帳返信）。 | 紙・園アプリ・電話／メール（システムが解釈・代行送信） |
| A4 | **家庭OS（システム）** | 提案・調整・代行を担う非人間アクター。 | 全アクターと接続 |

## 3. エピック一覧

| ID | エピック | ねらい |
|---|---|---|
| **E1** | 保育園情報の自動取り込み・解釈 | 紙・お便り・連絡帳を「読まなくていい」状態にする |
| **E2** | 持ち物・準備の自動化 | 「明日何が要るか」を考えなくていい状態にする |
| **E3** | 連絡帳・園コミュニケーション代行 | 園への連絡を「書かなくていい・送らなくていい」状態にする |
| **E4** | 夫との家事分担と自走化 | 夫との交渉・調整を「やらなくていい」状態にし、夫が美咲を経由せず自走できるようにする |
| **E5** | 「考えなくていい」体験の統合 | 司令塔の権限をシステムにオプトイン委譲する基盤 |
| **E6** | コンテキストトリガ自動化（位置・天気・音声） | 美咲がトリガを引かなくても、環境イベントから家庭運営が自動発火する |

## 4. ユーザーストーリー

各ストーリーは Connextra 形式とし、以下を付与する:
- **AC**: 受け入れ基準（Acceptance Criteria）
- **優先度**: Must / Should / Could
- **ダメにする軸**: 判断 / 調整 / 記憶 / 実行 のうち、奪う対象

---

### エピック E1: 保育園情報の自動取り込み・解釈

#### US-01: お便り自動解釈
- **As a** 美咲
- **I want** 保育園から受け取った紙のお便りや連絡帳を写真で送るだけで、内容を自動で構造化してほしい
- **So that** 毎週何枚もの紙を自分で読み解いて要点を抜き出す手間を完全になくしたい
- **AC**:
  - お便り画像をアップロードすると、行事・持ち物・期日・対象クラスが自動抽出され一覧表示される
  - 抽出結果から「カレンダー登録」「TODO化」がワンタップで実行できる
  - 解釈失敗時は人間に確認を求めるが、再入力は不要（再撮影だけ）
- **優先度**: Must
- **ダメにする軸**: 判断・記憶

#### US-02: 行事・予定の自動カレンダー反映
- **As a** 美咲
- **I want** 抽出された保育園の行事・休園・面談予定を自動で家族カレンダーに反映してほしい
- **So that** 「カレンダーに入れ忘れた」事故から永久に解放されたい
- **AC**:
  - 抽出された予定は美咲・夫の両カレンダーに自動反映される（オプトイン時）
  - 重複予定・既存予定との衝突を検知してアラートする
  - 「自動反映ON/OFF」が領域単位で切替できる
- **優先度**: Must
- **ダメにする軸**: 判断・記憶・実行

---

### エピック E2: 持ち物・準備の自動化

#### US-03: 明日の持ち物リスト自動生成
- **As a** 美咲
- **I want** 毎晩、翌日の保育園の持ち物リストを自動生成して通知してほしい
- **So that** 寝る前に「明日何が要ったっけ」を脳内で再構築する作業をやめたい
- **AC**:
  - 曜日固定の持ち物・行事連動の持ち物・季節持ち物を統合した最終リストが提示される
  - 各アイテムに「家にあるか」のチェック状態が付く
  - 「全部準備済みにする」ワンタップ承認が可能
- **優先度**: Must
- **ダメにする軸**: 判断・記憶

#### US-04: 期日逆算の自動準備（消耗品・季節アイテム統合）
- **As a** 美咲
- **I want** おむつ・着替え等の消耗品の不足、および運動会・プール開き・制作物などの行事準備を、期日から逆算して自動でTODO化／自動補充してほしい
- **So that** 在庫の頭の片隅監視と「来週プールだった！」型の直前焦りを両方やめたい
- **AC**:
  - 消耗品: 消費ペース推定から不足予測日を算出。「自動注文ON」品目は既定ECで自動発注し事後通知。上限金額・頻度を設定可能
  - 行事アイテム: 園情報（US-01）から行事を検出し、必要物・準備期限・担当（美咲 or 夫）を自動提示
  - 行事準備TODOはE4（家事分担）と連携して夫へ振り分け可能
- **優先度**: Should
- **ダメにする軸**: 判断・記憶・実行

> **US-05**: US-04 に統合されたため欠番。

---

### エピック E3: 連絡帳・園コミュニケーション代行

#### US-06: 連絡帳の自動下書き
- **As a** 美咲
- **I want** 子の今日の様子（夕食・睡眠・体温・機嫌）を入力すると、保育園連絡帳の文面を自動下書きしてほしい
- **So that** 毎晩あの定型文を考えてひねり出す作業をやめたい
- **AC**:
  - 数項目のチェック入力から、丁寧体の連絡帳文面が自動生成される
  - 美咲は「そのまま送信」または軽微編集だけで完了できる
  - 過去の文面トーンを学習し、家庭らしい文体になる
- **優先度**: Must
- **ダメにする軸**: 判断・実行

#### US-07: 欠席・遅刻・お迎え変更の代行連絡（オプトイン）
- **As a** 美咲
- **I want** 子の発熱や予定変更があったとき、保育園への連絡を自動で送信してほしい
- **So that** 朝の混乱の最中に園アプリを開いて連絡文を打つ動作から解放されたい
- **AC**:
  - 「欠席」「遅刻○時」「お迎え夫に変更」をタップ1回で園に送信できる
  - オプトイン設定時、特定トリガ（37.5℃以上検知 等）で自動送信される
  - 送信後の事後通知が美咲・夫の両方に届く
- **優先度**: Should
- **ダメにする軸**: 調整・実行

---

### エピック E4: 夫との家事分担と自走化

#### US-08: タスクの夫への自動アサイン
- **As a** 美咲
- **I want** その日発生する家事・育児タスクを、夫の勤務予定・残業状況を踏まえて自動でアサインしてほしい
- **So that** 「これ夫に頼んでいいんだっけ」と毎回判断する作業をやめたい
- **AC**:
  - 夫のカレンダー（勤務・会議）と連携し、対応可能な時間帯にタスクを割り付ける
  - 美咲はアサイン結果を一覧で確認、ワンタップで承認できる
  - オプトイン時、承認なしで夫に直接通知される
- **優先度**: Must
- **ダメにする軸**: 判断・調整

#### US-09: 夫の自走化UI（タスク表示＋園・子セルフサーブ）
- **As a** 夫
- **I want** 自分のHomePilotから当日タスク・締切・場所を把握できるだけでなく、保育園や子に関する連絡・対応を妻を経由せずに直接実行したい
- **So that** 「俺、今日何やればいい？」「これ園にどう伝えればいい？」を毎回妻に聞かずに自走したい
- **AC**:
  - 当日タスクが優先順・時刻順で表示され、「完了」「やれない」が即操作可能
  - 「やれない」を押すと自動で再アサインフローが走る
  - 夫モード専用画面から園への連絡（欠席・遅刻・お迎え変更）を直接送信できる（共同親権モード）
  - 夫の操作・完了報告はシステム経由で美咲に**静かに**伝達され、美咲のスマホには通知音は鳴らない
- **優先度**: Must
- **ダメにする軸**: 判断・調整・実行

#### US-10: 夫婦コミュニケーションのトーン緩衝
- **As a** 美咲
- **I want** 夫へのタスク依頼や指摘が、自動で柔らかいトーンに変換されて伝わってほしい
- **So that** 自分の苛立ちが家庭内コミュニケーションに直接漏れて空気が悪くなる事を回避したい
- **AC**:
  - 美咲が入力した依頼文は、夫に届く前に「依頼」トーンに自動整形される
  - 緊急度に応じて整形強度が変わる（緊急時はストレート）
  - 元文と整形後の両方を後から確認できる
- **優先度**: Should
- **ダメにする軸**: 調整

---

### エピック E5: 「考えなくていい」体験の統合

#### US-11: 「今日これだけ」ホーム画面
- **As a** 美咲
- **I want** アプリを開いた瞬間に「今日やるべきこと／自動でやっておいたこと」だけが表示されてほしい
- **So that** 複数アプリを横断して頭で再統合する作業をやめたい
- **AC**:
  - ホーム画面は「今やる（人間アクション）」「自動完了済」「夫担当」の3ブロックで構成される
  - 各項目はワンタップで詳細展開／承認／取消ができる
  - 通知は1日のまとまった時間にダイジェスト配信される
  - ダイジェストはルーチン系通知が対象。緊急系通知（US-07 の発熱時自動連絡、US-16 の「お迎えバトン引継ぎ」等）は即時通知される
- **優先度**: Must
- **ダメにする軸**: 判断・記憶

#### US-12: 一括承認＆領域別オプトイン自動実行制御
- **As a** 美咲
- **I want** システムからの提案を「全部OK」とまとめて承認でき、かつ領域別（持ち物/補充/連絡/タスク振り分け 等）に自動実行モードをON/OFF設定したい
- **So that** 提案を1つずつ判断する負荷を消し、「ここは任せる、ここは見たい」のコントロールも自分で握っていたい
- **AC**:
  - **「一括承認」**: ホーム画面の「すべて承認」ボタンで未処理の提案をまとめて承認できる
  - **「自動承認」**: 領域単位で「次回から自動承認」をONにできる（提案→承認のステップを省略し、提案発生時点で承認扱い）
  - **「自動実行」**: 領域単位で自動実行モードのON/OFFスイッチがあり、「何が自動化されるか」「停止方法」が各スイッチに明示される（提案そのものをスキップして実行）
  - 重大判断（高額注文・園への正式連絡 等）は自動承認・自動実行の対象から原則除外される
  - ただしユーザーが個別オプトインで明示同意した項目（例: US-07 の発熱時自動連絡、US-04 の上限金額内自動注文）は除外の対象外とする
  - 除外/対象の境界は各領域ストーリーで定義される条件（US-04 の上限金額、US-07 のオプトイン条件 等）に従う
  - 自動実行履歴は事後参照可能（US-14と連動）
- **優先度**: Must
- **ダメにする軸**: 判断・実行

> **US-13**: US-12 に統合されたため欠番。

#### US-14: 事後報告ログ
- **As a** 美咲
- **I want** システムが自分の代わりに行った行動（注文・連絡・夫へのアサイン等）を一覧で事後確認したい
- **So that** 任せきっても安心できる、最低限のトレーサビリティだけ確保したい
- **AC**:
  - 全自動実行が時系列で表示される
  - 各項目から取消・夫への共有・コメントが可能
  - 過去◯日分の検索が可能
- **優先度**: Should
- **ダメにする軸**: 記憶（任せた行動の保持責任もシステム側）

#### US-15: 司令塔バトンタッチ（夫モード）
- **As a** 美咲
- **I want** 自分が体調不良・出張等で動けない時、家庭OSの「司令塔」を一時的に夫に切り替えたい
- **So that** 自分が倒れても家庭が止まらない安心感を得たい
- **AC**:
  - 「司令塔=夫」に切り替えると、提案・通知の主宛先が夫に変わる
  - 切替期間を期日指定できる
  - 期間終了後は自動で美咲に戻る
  - 切替中、夫の端末でホーム画面（US-11 相当）と事後報告ログ（US-14 相当）が**司令塔ビュー**として表示される
- **優先度**: Could
- **ダメにする軸**: 判断・調整・実行

### エピック E6: コンテキストトリガ自動化（位置・天気・音声）

#### US-16: 位置・天気コンテキストトリガ自動実行
- **As a** 美咲
- **I want** 位置イベント（保育園着・帰宅・夫の退社）と天気イベント（雨・暑熱・寒波予報）に連動して、必要な準備や調整が自動発火してほしい
- **So that** 「あ、〇〇しなきゃ」「今日雨だから長靴…」と自分で気づく作業すらやめたい
- **AC**:
  - 位置トリガ: 保育園到着→「登園済」自動更新／お迎え予測時刻を夫に共有／帰宅検知→ 夕飯導線（解凍・着替え・お風呂順序）を提示／夫の退社検知→ お迎えバトン引継ぎ通知（オプトイン時は美咲を経由せず直接）
  - 天気トリガ: 雨予報→ 長靴・カッパを翌日持ち物リスト（US-03）に自動追加し玄関配置リマインド／猛暑予報→ 帽子・大型水筒・冷感タオル追加／寒波予報→ 防寒着追加。前夜と当朝の2回通知
  - 「お迎えバトン引継ぎ」は US-08（夫へのタスクアサイン）でお迎えタスクが夫に割り当て済みであることを前提とする
  - 各トリガは領域別オプトイン制御（US-12）に従う
- **優先度**: Should
- **ダメにする軸**: 判断・調整・実行

#### US-17: 音声ワンショット代行
- **As a** 美咲
- **I want** 手が塞がっている朝に「HomePilotに依頼: 〇〇発熱」と1フレーズ言うだけで、欠席連絡・夫通知・予定再調整が並列実行されてほしい
- **So that** 子を抱えながらスマホを操作する地獄から解放されたい
- **AC**:
  - スマホ音声アシスタント連携で起動可能
  - 1音声トリガで複数アクション（園連絡＋夫通知＋カレンダー再調整＋必要物の自動補充）が並列発火
  - 完了は通知またはホーム画面（US-11）で進捗表示
  - 実行内容は事後報告ログ（US-14）に残る
- **優先度**: Should
- **ダメにする軸**: 判断・調整・実行

## 5. 非機能要件

ユーザーからの追加要件指定はなし。技術的非機能要件（性能・可用性・プライバシー等）は実装フェーズで別途定義する前提。
唯一の制約として **AWS上で稼働すること** を満たすこと。

---

## 6. スコープ外（Out of Scope）

本MVPでは以下を扱わない（将来拡張で検討）:
- 献立・買い物・冷蔵庫在庫管理
- 子どもの体調・通院判断（医療判断系）
- 送迎調整・天候連動の交通判断
- 家計管理・サブスク管理
- 第二子以降の子ども別個別対応の高度化（基本対応のみ）
- 保育園以外の施設（学童・習い事）連携

## 7. ハッカソン評価軸とのトレース

| 評価観点 | 本ストーリー集での対応 |
|---|---|
| ビジネス意図(Intent)の明確さ | §1.2 コンセプト＋§1.3 ペルソナで「何故ダメにするか」を明示 |
| Unit分解の適切さ | §3 エピック5本＋§4 ストーリー15本で粒度を揃え相互依存を示す |
| 創造性・テーマ適合性 | 各ストーリーに「ダメにする軸（判断/調整/記憶/実行）」を付与しテーマ整合を可視化 |
| ドキュメント品質 | Connextra形式・受け入れ基準・優先度を全ストーリーに付与 |
