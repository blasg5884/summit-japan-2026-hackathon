# ユーザーストーリー作成 計画書

## 背景

- ハッカソン: **AWS Summit Japan 2026 AI-DLC ハッカソン**
  - テーマ: 「人をダメにするサービス」
  - サービス自体がAIを使う必要はなく、「人をダメにできるアイデア」自体が評価対象
  - 書類審査の提出物に「Inceptionフェーズの成果物（設計ドキュメント等）」が含まれる
- 対象ペルソナ: **中村 美咲（36歳・共働きPM・6歳/2歳の子持ち）**
  - 本質的悩み: 家事ではなく「家庭全体の意思決定負荷」
  - 求める価値: 効率化ではなく「判断負荷の削減」「考えること自体からの解放」
- 本ドキュメントの目的: 上記システムを開発するための **契約となる、明確に定義されたユーザーストーリー** を作成する。

---

## 進め方の原則

- 各ステップは順次実行し、完了したらチェックを付ける（`[x]`）。
- PMとしての独自判断は行わない。判断が必要な箇所はすべて `[Question]` として明示し、ユーザーの `[Answer]` を待ってから進める。
- 計画作成後、まずレビュー・承認を受ける。承認後に1ステップずつ実行し、ステップ完了ごとにレビューを依頼する。
- 全成果物は日本語で生成する。

### ステップ 1: プロダクト方向性の確定（前提質問）

ユーザーストーリーの粒度・対象を決める前に、以下を確定する必要がある。

- [x] サービスの核となるコンセプトを確定する

[Question 1-1] 「人をダメにする」の方向性として、どの路線を採用しますか？
  (A) 家庭運営の意思決定を全面代行する「家庭OS／執事AI」路線
  (B) 美咲の脳内タスクを片っ端から先回り処理する「ぐうたら化エージェント」路線
  (C) 家族（夫・子）への指示出し・調整まで巻き取る「家庭の司令塔代行」路線
  (D) その他（自由記述）

[Answer 1-1] A,C を重視したいです。

[Question 1-2] MVP（予選デモ用最小プロダクト）で扱う家庭領域はどれに絞りますか？（複数選択可）
  - 献立・買い物・在庫管理
  - 保育園関連（持ち物・連絡帳・行事）
  - 家事分担（夫との調整）
  - 子どもの体調・通院判断
  - スケジュール・送迎調整
  - その他

[Answer 1-2] 最優先：保育園関連（持ち物・連絡帳・行事）、第２優先：家事分担（夫との調整）でお願いします。

[Question 1-3] プロダクトの提供形態は？（決め打ち or 候補から選択）
  - スマホアプリ / Webアプリ / LINE Bot / 音声(スマートスピーカー) / その他

[Answer 1-3] スマホアプリ。

[Question 1-4] ストーリーに登場させるアクター（ユーザー種別）は？
  - 美咲のみ / 美咲＋夫 / 美咲＋夫＋子ども / ＋保育園 / その他

[Answer 1-4] 美咲、夫、保育園

[Question 1-5] 「人をダメにする度合い」はどのレベルまで踏み込みますか？
  (A) 提案するだけ（最終判断は人間）
  (B) デフォルトで自動実行、止めたい時だけ人間が介入
  (C) 完全自動・通知すらしない（事後報告のみ）

[Answer 1-5] A、オプトイン形式で自動実行も可能にしたいです。
