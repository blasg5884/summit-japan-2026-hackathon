# ユーザーストーリーのユニット分割 計画書

## 背景・目的

- 入力: [aidlc-docs/inception/user_stories.md](../user_stories.md)（HomePilot のユーザーストーリー15本／6エピック）
- 目的: 並行開発可能な **作業ユニット（境界づけられたコンテキスト）** にユーザーストーリーをグループ化する
- 各ユニットの要件:
  - サブドメインまたはビジネスロールに沿っていること
  - 単一チームで構築可能な高い凝集性を持つこと
  - ユニット間の結合度が低いこと（並行開発可能）
- 出力先: `aidlc-docs/inception/units/<unit_name>.md`（ユニットごとに1ファイル）
- 制約: **追加の設計詳細は生成しない**。各ユニットファイルにはユーザーストーリーと受け入れ基準のみを記載する。

---

## 進め方の原則

- 各ステップは順次実行し、完了後にチェック (`[x]`) を付ける
- アーキテクトとしての独自判断は行わない。判断が必要な箇所は `[Question]` で明示し、`[Answer]` を待つ
- 計画作成後、まずレビュー・承認を受ける。承認後に1ステップずつ実行
- 全成果物は日本語で生成する

### ステップ 2: ユニット分割方針の確定（質問あり）

[Question 2-1] ユニット分割の主軸は何にしますか？
  - (A) サブドメイン（業務領域：保育園系／夫婦系／在庫系 等）で分ける
  - (B) ビジネスロール（誰のための機能か：美咲向け／夫向け／システム自走 等）で分ける
  - (C) 機能層（情報取込／推論／実行／UI 等）で分ける
  - (D) 上記のハイブリッド

[Answer 2-1] A

[Question 2-2] ユニット数の目安はありますか？
  - (A) 3〜4個（粗め）
  - (B) 5〜6個（中粒度）
  - (C) 7個以上（細かめ）
  - (D) 任せる（ストーリーの凝集度に従って自然分割）

[Answer 2-2] B

[Question 2-3] ユニットファイル名の言語は？
  - (A) 日本語（例: `保育園情報.md`）
  - (B) 英語スネークケース（例: `nursery_information.md`）
  - (C) 英語ケバブケース（例: `nursery-information.md`）

[Answer 2-3] C

[Question 2-4] 1つのユーザーストーリーが複数ユニットに跨る場合、どう扱いますか？
  - (A) 主担当ユニットにのみ配置し、他ユニットには参照リンクを置く
  - (B) 重複して配置する（同じACが複数ファイルに出現する）
  - (C) ユニット分割を見直して跨りを発生させない
  - (D) ケースバイケースで判断（→質問する）

[Answer 2-4] A
