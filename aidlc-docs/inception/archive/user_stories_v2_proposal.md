# HomePilot ユーザーストーリー v2 提案
## 〜現状60% → 100% への引き上げ案〜

---

## 1. 自己評価: 現状の15本は何が「60%」なのか

### 1.1 ペルソナのペインポイント（再掲）

中村美咲の本質的悩みは「家事」ではなく、以下の **連続する小さな判断・調整・記憶** によって脳が慢性疲労していることである。

| ペイン領域 | 具体例（ペルソナ記述より） |
|---|---|
| **常時並列処理** | 朝・昼・夜とも複数タスクを同時並行で意思決定 |
| **アンビエント記憶負担** | 冷蔵庫在庫、おむつ残量、牛乳残量を頭の片隅で監視 |
| **状態予測** | 子の体調、夫の残業、雨天時の送迎、家族の機嫌、睡眠不足 |
| **司令塔依存** | 「自分が止まると家庭が止まる」恐怖 |
| **夜の脳内シミュレーション** | 寝る前に翌日の家庭運営を頭の中でリハーサルしている |
| **本音** | 「考えること自体をやめたい」 |

### 1.2 現状15本のギャップ（厳しめレビュー）

| ギャップ | 現状の限界 |
|---|---|
| **G1. 受動的すぎる** | US-01〜07の多くが「美咲がトリガを引いてから動く」設計。先回り（プリエンプション）が弱く、結局美咲が"気づく"必要がある。 |
| **G2. 通知ノイズが減らない** | 既存アプリ（園アプリ、LINE、カレンダー）からの通知が美咲のスマホに届き続ける限り、認知負荷は減らない。HomePilotが「通知の前に立つ」発想がない。 |
| **G3. アンビエントな状態管理が無い** | 在庫・体調・機嫌・天候・夫の予定など、ペルソナが日常監視している"環境変数"を継続的に読み続ける機能が弱い（US-04の消耗品のみ）。 |
| **G4. コンテキストトリガが弱い** | 位置情報・時刻・健康データ・家族カレンダー連動の自動発火がない。スマホアプリの最大の強みを使っていない。 |
| **G5. 夜のリハーサル代行が無い** | ペルソナの最重要疲労源（翌日シミュレーション）に対して、"明日のリハーサルを代わりに回す"機能が無い。 |
| **G6. 夫のセルフサーブ化が弱い** | US-08〜10は「美咲が夫を管理する」構図のまま。本当の解放は「夫が美咲を経由せず園・子と直接動ける」状態。 |
| **G7. 入力負荷が残っている** | US-06「項目を入力すれば下書き」のように、美咲の入力前提が多い。本来は「入力ゼロ＝センシング/連携で勝手に把握」が理想。 |
| **G8. 一気通貫のフェイルオーバー無し** | 「美咲が倒れた／出張」など司令塔不在時に **完全自動運転に切り替わる** 体験が US-15 の手動切替どまり。 |

## 2. ネイティブアプリだからこそ解決できる領域

スマホネイティブアプリでなければ実現できない・実現が著しく難しい機能群を、HomePilotの差別化軸として最大限活用する。

| プラットフォーム能力 | HomePilot での活用余地 |
|---|---|
| **通知の受信側になれる（NotificationListener / Notification Service Extension）** | 園アプリ・LINE・自治体アプリの通知を **美咲に届く前に傍受**し、要対応だけ抽出して残りは沈黙 |
| **ロック画面ウィジェット / Live Activity** | 「今日これだけ」をアプリを開かなくても常時露出。認知摩擦ゼロ |
| **位置情報（バックグラウンド）** | 保育園着で欠席連絡自動解除、帰宅検知で夕飯導線、コンビニ通過時に不足品リマインド |
| **HealthKit / 体温計・睡眠デバイス連携** | 子の体温・睡眠から「今日は荒れる」を朝予測。美咲が観察する前に通知 |
| **共有シート / インテント** | カメラロール・メール・園アプリから **ワンタップでHomePilotに流し込み** |
| **音声アシスタント連携（Siri Shortcut / App Action）** | 手が塞がってる朝に「美咲ちゃん、◯◯発熱」とつぶやくだけで、欠席連絡＋夫通知＋予定調整が並列実行 |
| **常時バックグラウンド処理** | 在庫・予定・天気・夫予定を24h監視して状態変化に即応 |
| **プッシュ通知の能動制御** | 「今は通知しない／夫に転送する／一括ダイジェスト化」を司令塔代行として制御 |
| **デバイス間連携（Family Sharing / Watch）** | 夫のスマホ・Apple Watch にも独立UIを出し、夫を**自走化**させる |
| **カメラ即起動 + OCR/物体認識（オンデバイス）** | リュックの中身、冷蔵庫、お便りを瞬時に解釈 |

## 3. 100%版ユーザーストーリー提案（差分案）

現状15本のうち、コアは残しつつ、**新規10本（US-16〜25）を追加**＋**3本を強化（US-01/06/15）**することで100%に引き上げる案。

### 凡例
- 🆕 = 新規ストーリー
- ♻️ = 既存ストーリーの強化版（差し替え提案）

---

### 新カテゴリ E6: 通知の遮断と統合（"美咲のスマホの前に立つ"）

#### 🆕 US-16: 通知ジャック
- **As a** 美咲
- **I want** 園アプリ・LINE・カレンダー等から自分のスマホに届くはずだった家庭関連通知を、HomePilot が先に受け取って整理してほしい
- **So that** スマホがピコピコ鳴るたび反射的に確認する条件反射から解放されたい
- **AC**:
  - 連携対象アプリの通知を受信／要約／要対応だけ昇格表示する
  - 「夫マター」「保育園マター」「美咲マター」に自動仕分け
  - 美咲には1日3回（朝・昼・夜）のダイジェストのみ届く（オプトインで都度通知も可）
- **優先度**: Must / **ダメにする軸**: 判断・記憶
- **ネイティブ依存**: NotificationListener / Notification Service Extension

#### 🆕 US-17: ロック画面「今日これだけ」常時表示
- **As a** 美咲
- **I want** ロック画面ウィジェットに「今日の自分／夫／子」の3行だけが常時露出してほしい
- **So that** アプリを開く動作すら省きたい
- **AC**:
  - ウィジェットに次の3行: 「自分: 〇〇」「夫: 〇〇」「子: 〇〇」
  - 緊急時のみ赤色の1行に圧縮表示
  - タップで該当タスクを直接承認できる
- **優先度**: Must / **ダメにする軸**: 判断・記憶
- **ネイティブ依存**: WidgetKit / Live Activity / App Widgets

---

### 新カテゴリ E7: コンテキストトリガ自動化（"位置・時刻・センサで勝手に動く"）

#### 🆕 US-18: 位置トリガ自動実行
- **As a** 美咲
- **I want** 保育園着・帰宅・夫の退社など位置イベントに連動して、関連処理が自動発火してほしい
- **So that** 「あ、〇〇しなきゃ」と気づく作業すらやめたい
- **AC**:
  - ジオフェンス: 保育園到着→ "登園済" 自動更新／お迎え予測時刻を夫に共有
  - 帰宅検知→ 夕飯導線（解凍・着替え・お風呂順序）を提示
  - 夫の退社検知→ お迎えバトン引継ぎ通知（オプトイン時は美咲を経由せず直接）
- **優先度**: Should / **ダメにする軸**: 判断・調整・実行
- **ネイティブ依存**: Background Geofencing / Location Services

#### 🆕 US-19: 健康データ連動の状態予測
- **As a** 美咲
- **I want** 子の体温・睡眠・夫の睡眠・自分の月経データなどから「今日の家庭の荒れやすさ」を朝に予測してほしい
- **So that** 「今日は機嫌悪そう」を察する仕事をやめたい
- **AC**:
  - HealthKit / 連携体温計 / スマートマット等のデータから家庭リスク指数を算出
  - リスク高日は予定を自動で軽量化提案（夕飯=デリ、入浴=シャワー、寝かしつけ=夫担当）
  - 予測の根拠（誰のどのデータか）は事後参照可
- **優先度**: Could / **ダメにする軸**: 判断・記憶
- **ネイティブ依存**: HealthKit / Health Connect

#### 🆕 US-20: 音声ワンショット代行
- **As a** 美咲
- **I want** 手が塞がってる朝に「HomePilotに依頼: 〇〇発熱」と1フレーズ言うだけで、欠席連絡・夫通知・予定再調整が並列実行されてほしい
- **So that** 子を抱えながらスマホを操作する地獄から解放されたい
- **AC**:
  - Siri Shortcut / App Action から起動可能
  - 1音声トリガで複数アクション（園連絡＋夫通知＋カレンダー再調整）が並列発火
  - 完了は Live Activity で進捗表示
- **優先度**: Should / **ダメにする軸**: 判断・調整・実行
- **ネイティブ依存**: SiriKit / App Intents / App Actions

---

### 新カテゴリ E8: 脳内シミュレーション代行（"夜のリハーサルを引き取る"）

#### 🆕 US-21: 朝の出発リハーサル予測
- **As a** 美咲
- **I want** 起床時刻に「今日の朝、ここでつまづく」を先回りで通知してほしい
- **So that** 自分で頭の中でシミュレーションする前に答えが来てほしい
- **AC**:
  - 天気・夫の予定・園の行事・子の体調を統合して「今朝の詰まりポイント」を3つまで通知
  - 例: 「雨→ 7:40登園で長靴必要」「夫9時会議→ お迎え不可」「子睡眠5h→ 朝食簡素モード推奨」
  - 各項目は対策込みで提示され、ワンタップ承認で全部実行される
- **優先度**: Must / **ダメにする軸**: 判断・記憶

#### 🆕 US-22: 夜のリハーサル音声ブリーフィング
- **As a** 美咲
- **I want** 22時に「明日の家庭リハーサル」を音声で読み上げてほしい
- **So that** ベッドでぼーっと聞いて承認するだけで、頭の中の翌日シミュレーションを完全に外注したい
- **AC**:
  - 音声ブリーフィング: 「明日は雨です。長靴を玄関に置きました。夫は9時会議のためお迎えは美咲さんです。下の子のおむつが残り3枚なので明日の宅配で補充済みです」
  - 聞きながら「承認」「変更」を音声で返答できる
  - スリープ後はアプリが自動終了
- **優先度**: Must / **ダメにする軸**: 判断・記憶
- **ネイティブ依存**: Background Audio / SiriKit

---

### 新カテゴリ E9: 夫の自走化（"美咲を経由しないルートを作る"）

#### 🆕 US-23: 夫セルフサーブUI
- **As a** 夫
- **I want** 自分のHomePilotから保育園・子・家事タスクと直接やり取りできる独立UIを使いたい
- **So that** 妻に「今日何やる？」と聞かなくても自走したい
- **AC**:
  - 夫モードの専用画面: 当日タスク／園連絡権限／買い物導線
  - 夫が完了報告するとシステム経由で美咲に静かに伝達（美咲のスマホは鳴らない）
  - 夫から園への連絡も代行可能（共同親権モード）
- **優先度**: Must / **ダメにする軸**: 調整

#### 🆕 US-24: 司令塔フェイルオーバー（自動切替）
- **As a** 美咲
- **I want** 自分のカレンダーで出張・会議集中・体調不良が検知されたら、自動的に司令塔が夫もしくは完全自動モードに切り替わってほしい
- **So that** 「自分が止まると家庭が止まる」恐怖を構造的に消したい
- **AC**:
  - トリガ: 出張カレンダー検知／高熱記録／"司令塔OFF"音声コマンド
  - 切替時、自動実行モードが「全領域ON」に昇格、通知は最小化
  - 復帰検知（帰宅・体温正常）で美咲モードへ自動回帰、不在中の決定ログを提示
- **優先度**: Must / **ダメにする軸**: 判断・調整・実行
- **既存US-15の強化版として置換**

---

### 新カテゴリ E10: 入力ゼロ化（"美咲が打たない"）

#### 🆕 US-25: 連絡帳の入力ゼロ自動生成
- **As a** 美咲
- **I want** 連絡帳の文面を、自分が何も入力しなくても完成された状態でレビューだけしたい
- **So that** 夜の最後の力を絞って入力する儀式をやめたい
- **AC**:
  - 入力源: 子の体温計／睡眠デバイス／夕食写真の物体認識／園からの連絡
  - 自動下書きが20時に通知、ワンタップ承認で送信予約
  - 編集不要率（=承認のみで送信した割合）をKPIとして可視化
- **優先度**: Must / **既存US-06の強化版として置換** / **ダメにする軸**: 判断・実行
